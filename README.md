# Questa

Прототип мобильного приложения для организации микро-ивентов.
Разрабатывается по документам проекта: «Техническое задание на платформу Questa»
и «Частное техническое задание на MVP» (магистратура ФОМ-150510, УрФУ).

## Что это

Приложение открывается по ссылке в браузере телефона и ведёт себя как нативное:
полноэкранный режим, иконка на домашнем экране, работа с камерой и геолокацией.
Устанавливать ничего не нужно — это снимает риск на защите прототипа.

## Стек

| Слой | Решение | Почему |
| --- | --- | --- |
| Клиент | React + TypeScript + Vite, PWA | Быстрая сборка, запуск с телефона по ссылке |
| Оформление | Tailwind CSS | Палитра и типографика из ЧТЗ 10.2 вынесены в токены |
| Данные | PostgreSQL (Supabase) | Реляционная СУБД из ТЗ 4.1.1 |
| Авторизация | Supabase Auth (JWT) | Схема access + refresh из ТЗ 4.1.3 |
| Чат | Supabase Realtime | Доставка сообщений в реальном времени, ЧТЗ 5.8 |
| Медиа | Supabase Storage (S3-совместимое) | Аватары, обложки, фото-задания |
| Квесты | LLM-генерация по контексту ивента | ТЗ 4.2.6 |

Отличие от production-архитектуры ТЗ (Flutter + Go + Kafka + MinIO) — осознанное:
для прототипа, который нужно показать с телефона, важнее скорость сборки и
отсутствие установки. Слой данных при этом тот же, что в ТЗ, — PostgreSQL.

## Структура репозитория

```
supabase/setup.sql     таблицы, правила доступа и шаблоны квестов
api/generate-quest.ts  ИИ-генерация квеста по контексту (ТЗ 4.2.6)
src/                   код приложения
```

Файлы из `supabase/` выполняются по порядку в SQL-редакторе Supabase:
сперва `setup.sql`, затем `002_photos_and_interests.sql`.
Скрипт проверен на PostgreSQL 16: 17 таблиц, 35 правил доступа, 6 шаблонов
квестов по 3 задания.

## Как получается квест

1. Организатор запускает квест после начала ивента.
2. Контекст ивента — название, описание, категория, адрес, число участников,
   интересы — уходит в `api/generate-quest.ts`, оттуда в модель.
3. Ответ модели проверяется по схеме: ровно три задания нужных типов, квиз из
   шести вопросов с корректными индексами ответов.
4. Если модель недоступна или ответ не прошёл проверку, берётся случайный
   шаблон из коллекции — квест у ивента будет в любом случае.

## Экраны

Собраны по макетам Figma: онбординг, регистрация с подтверждением почты,
выбор интересов, главная с рекомендациями, карта с фильтром по категориям,
создание ивента, карточка ивента в трёх режимах, чат, прогресс квеста с
заданиями и квизом, профиль с уровнем и статистикой.

Магазин из макетов в прототип не вошёл: по ЧТЗ 3.2 он относится к третьему
этапу, за пределы MVP.

## Два режима работы

Приложение читает адрес и ключ проекта Supabase из `.env`.

**Боевой режим** (ключи заданы) — настоящий вход по e-mail и паролю, данные
в PostgreSQL, чат через Realtime, стрик ежедневного входа, начисление QP и XP
с защитой от повторного зачисления.

**Демонстрационный режим** (ключей нет) — экраны наполняются данными из
`src/data/demo.ts`. Нужен для разработки и как страховка: если база окажется
недоступна, приложение всё равно откроется.

Собрать демонстрационную сборку: `VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npm run build`.

## Расхождения с документами

Разрешены в пользу ЧТЗ, кроме случаев, где это невозможно технически:

| Что | В документах | В прототипе | Почему |
| --- | --- | --- | --- |
| Уровень при 1700 XP | 4 на макете | 5 | По шкале ЧТЗ 5.12.4 |
| Длина кода подтверждения | 4 цифры (ЧТЗ 5.1.1) | 6 цифр | Задаётся почтовым шаблоном Supabase |
| Квиз | 1 вопрос (5.11.3) / 6 вопросов (5.12.1) | 6 вопросов | Иначе не сходится награда 30 QP |
| Геокодер | Яндекс (ТЗ 11.1) | Nominatim | Яндекс требует платного ключа |
| Карта | MapKit Яндекса | OpenStreetMap | То же |
| Магазин | Этап 3 | Не реализован | Вне MVP по ЧТЗ 3.2 |

## Запуск

```bash
npm install
npm run dev
```

Адрес проекта и публичный ключ лежат в `.env`. Ключ publishable не секрет:
он и так уезжает в браузер каждому посетителю, а данные защищают правила
доступа в базе. Секретный ключ (`sb_secret_…`) в репозитории не хранится и
приложению не нужен.

## Публикация

Ветка собирается и выкладывается на GitHub Pages автоматически
(`.github/workflows/deploy.yml`). Один раз нужно включить сам механизм:
**Settings → Pages → Source → GitHub Actions**.

## Состояние работ

Сделано:

- экраны по макетам Figma, публикация на GitHub Pages при каждом изменении;
- база PostgreSQL: таблицы, правила доступа, шаблоны квестов;
- вход по e-mail и паролю, профиль, стрик ежедневного входа;
- ивенты, слоты, автоматическое открытие чата при наборе группы;
- чат в реальном времени, чек-ин, выполнение заданий, начисление QP и XP.

- ИИ-генерация квестов через функцию Supabase, с проверкой ответа модели
  и откатом на шаблон;
- гео-задание: карта, расстояние до цели, таймер присутствия внутри радиуса;
- центр уведомлений и настройки: профиль, пароль, уведомления, удаление;
- анимации: переходы между экранами, появление сообщений, счёт очков.

- отмена ивента организатором и недельная квота на создание;
- процедурные аватары и никнеймы от модели.

Дальше по порядку:

1. Фото-задание: камера, загрузка снимка, проверка моделью.
   Хранилище для снимков уже настроено в `002_photos_and_interests.sql`.
2. Завершение ивента с итогами по QP и взаимная оценка участников.
3. Жалобы на пользователей, ивенты и сообщения.
4. Пустые состояния и поведение при потере связи.

Известные ограничения прототипа:

- подтверждение почты выключено — бесплатная квота Supabase 2–3 письма в час;
- фоновое отслеживание геолокации в браузере невозможно, таймер присутствия
  идёт только при открытом приложении;
- push-уведомления на iPhone требуют установки на домашний экран и iOS 16.4+.
